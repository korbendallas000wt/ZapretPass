
# ZapretPass

Графический менеджер для [zapret](https://github.com/bol-van/zapret) — инструмента обхода DPI-блокировок.

Позволяет подбирать рабочие стратегии обхода для заблокированных сайтов, искать универсальные стратегии для групп доменов и управлять сервисом через удобный интерфейс.

---

## Возможности

### Уже реализовано
- Управление systemd-сервисом zapret (старт/стоп/рестарт, статус)
- Определение текущего режима работы (whitelist / global)
- Неинтерактивный запуск `blockcheck.sh` через `BATCH=1` с передачей настроек переменными окружения и парсингом найденных стратегий
- Поиск универсальных стратегий через пересечение и объединение результатов
- Применение стратегий и режимов к конфигу запрута с автоматическим бэкапом
- Перехват SNI-доменов через tshark
- Проверка доступности сайтов через curl с классификацией вердиктов
- Управление whitelist доменов
- Именованные пресеты стратегий
- Кэширование пароля sudo с проверкой валидности
- `install.sh`: установка зависимостей, клонирование/обновление zapret, сборка бинарников, регистрация systemd-юнитов, создание launcher и desktop-ярлыка
- Система проверок и применения обновлений через raw-ветку `main` (`VERSION`, `docs/CHANGELOG.md`, ZIP): `core/updater.py`, `ui/about_dialog.py`, `ui/update_indicator.py`, файл `VERSION`
- ActivityGuard для операций обновления: блокировка повторных проверок/применения и защита от закрытия окна во время критических операций
- Ротация артефактов обновления: последние 3 бэкапа, 3 скачанных ZIP и 3 fallback-архива

### В активной разработке

- Тесты и полировка апдейтера: dry-run, rollback, ротация артефактов, восстановление exec-битов
- Интеграция обновлений в мастер первого запуска (при необходимости)
- Решение о роли GitHub Releases: оставить только fallback или использовать как дополнительный канал
- Qt6-интерфейс, основной сценарий — «Паспорт сайта»
- Продуктивный fast-режим: первая стратегия → применение → сниффер → фоновая валидация
- Двухфазный поиск вспомогательных доменов
- Предзагруженные списки вспомогательных доменов для популярных сайтов

## Архитектура

Приложение разделено на слои:

1. **core/** — ядро, бизнес-логика без привязки к UI. Ни один модуль не импортирует Qt.
2. **core/scenarios.py** — декларативные сценарии и блоки workflow.
3. **ui/** — графический интерфейс на Qt6, исполняет сценарии.

Это позволяет:
- Тестировать логику отдельно через Python-скрипты
- Менять интерфейс без переписывания ядра
- Использовать ядро из командной строки

Подробнее о модулях — в [PROJECT_MANIFEST.md](docs/PROJECT_MANIFEST.md).

## Требования

- **ОС:** Linux с systemd. Установщик поддерживает Ubuntu/Debian-based 24.04+, Manjaro/Arch и Fedora 40+; протестировано на Manjaro и Ubuntu 24.04.
- **Python:** 3.10+ (для PyQt6)
- **Графический стек:** PyQt6 и QtWebEngine (устанавливаются `install.sh`)
- **Движок:** `zapret` в `/opt/zapret` (клонирование/обновление и сборка выполняются `install.sh`)
- **Базовые утилиты:** `git`, `curl`, `make`, `gcc`, dev-пакеты для netfilter/libcap/libmnl/systemd (ставятся установщиком)
- **Сниффер:** `tshark` из пакета `wireshark-cli` — требуется для перехвата SNI; установщик пока не ставит его автоматически
- **Диалоги пароля:** `kdialog` (KDE) или fallback `QInputDialog`
- **Привилегии:** sudo или pkexec для управления сервисом, конфигом и запуска `blockcheck`
- **Сеть:** доступ к `raw.githubusercontent.com` для `VERSION` и `docs/CHANGELOG.md`, а также к `github.com` для ZIP-архива `main`; GitHub Releases API — fallback для release notes. При ошибке сети обновление просто не показывается.
- **Данные апдейтера:** временные `downloads/staging` в `~/.cache/zapretpass`; постоянные бэкапы и fallback-архивы в `~/.local/share/zapretpass`
- **Осторожно в dev:** встроенный апдейтер заменяет верхнеуровневые элементы из `main` ZIP; для разработки предпочтителен `git pull`. Внутренние файлы должны жить в `Work/`, exec-биты восстанавливаются автоматически.

## Установка

Рекомендуется использовать `install.sh` из корня проекта. Он устанавливает зависимости, ставит/обновляет `zapret`, собирает бинарники при необходимости, регистрирует systemd-юниты, создаёт launcher и desktop-ярлык.

Склонировать репозиторий и установить:

```bash
git clone https://github.com/korbendallas000wt/ZapretPass.git
cd ZapretPass
git checkout dev
chmod +x install.sh
./install.sh
```

Запустить приложение:

```bash
./zapretpass.sh
```

> Portable-режим: `PROJECT_DIR` вычисляется относительно исходного кода, поэтому проект можно держать в любой директории (например, `~/Scripts/ZapretPass` или `~/SOFT/ZapretPass`). После перемещения папки рекомендуется перезапустить `install.sh` из нового местоположения.

> В dev предпочтителен `git pull`. Встроенный апдейтер можно использовать для проверки релизного цикла, но он заменяет верхнеуровневые элементы из `main` ZIP; внутренние файлы держи в `Work/`.

## Использование (после релиза UI)

UI находится в активной разработке. Основной сценарий — «Паспорт сайта»:

1. Запустить приложение через `./zapretpass.sh` или ярлык в меню.
2. Ввести пароль sudo при первом привилегированном действии.
3. Выполнить диагностику доступности домена.
4. При блокировке запустить `blockcheck` для подбора стратегий.
5. Сохранить найденные стратегии и вспомогательные домены в паспорт сайта.
6. Применить выбранную стратегию к конфигу `zapret` и проверить работу сервиса.

Приложение проверяет новую версию по файлу `VERSION` в ветке `main`, берёт текст обновления из `docs/CHANGELOG.md` (fallback — GitHub Release body), скачивает ZIP-архив `main`, создаёт бэкап в `~/.local/share/zapretpass/backups`, применяет обновление, восстанавливает exec-биты и ротирует старые артефакты.

## Структура проекта

```text
ZapretPass/
├── zapretpass.py      # Точка входа приложения
├── install.sh         # Установщик зависимостей и движка zapret
├── VERSION            # Текущая версия приложения
├── core/              # Ядро: бизнес-логика, независимая от UI
│   └── updater.py     # Проверка и применение обновлений
├── ui/                # Qt6-интерфейс (в активной разработке)
│   ├── about_dialog.py    # Диалог «О программе» и обновлений
│   └── update_indicator.py # Индикатор доступного обновления
├── data/              # Данные приложения (создаются автоматически)
├── resources/         # Ресурсы приложения
├── docs/              # Документация проекта
├── legacy/            # Старый код и бэкапы (локально, вне git)
└── Repo/              # Staging для релизов в main (локально, вне git)
```
