# Changelog

Все значимые изменения проекта документируются в этом файле.

## Unreleased / dev

Дата состояния: 2026-11-02. Ветка: `dev`. Готовится релиз `1.3.0`.

### Что нового для пользователя

- ZapretPass теперь проще устанавливается на разные Linux-системы: установщик сам определяет доступный способ управления сервисом — `systemd`, `OpenRC`, `runit`, `s6` или `sysvinit` — и настраивает автозапуск `zapret`.
- Если обычная init-система недоступна, например в контейнере, WSL или chroot, остаётся запасной режим через daemon-скрипт.
- Восстановление эталонных настроек теперь возвращает не только основной конфиг `zapret`, но и список доменов `whitelist`. Откат к базовому состоянию стал более предсказуемым.
- Чистая установка больше не должна спотыкаться на резервных копиях конфига, если системный конфиг ещё не создан.
- Ошибки ввода sudo-пароля и отмена привилегированных действий обрабатываются аккуратнее: меньше шансов остаться в непонятном состоянии или получить падение интерфейса.
- Визуальная диагностика и инструменты, добавленные в `v1.2.0`, остаются частью релизного среза: `Geo → DNS → HTML`, мини-браузер и инструмент «Целевые домены».

### Исправлено и улучшено

- Улучшена установка на дистрибутивах без `systemd` или с альтернативными init-системами.
- Улучшена логика сборки `zapret`: пакеты и команды для `systemd` используются только когда `systemd` действительно обнаружен.
- Улучшено восстановление baseline: теперь восстанавливаются и конфиг, и whitelist.
- Улучшена обработка ошибок аутентификации в интерфейсе.
- Упрощён состав репозитория: runtime-каталог `data/` больше не хранится в git, а эталонные конфиги и списки вынесены в `assets/defaults/`.

### Технические изменения

- `install.sh` переведён на многослойную логику без глобального `set -e`, чтобы установка ядра не падала из-за проблем с UI-зависимостями.
- Добавлено определение init-систем: `systemd`, `openrc`, `runit`, `s6`, `sysvinit`.
- Добавлен `scripts/zapretpass-daemon.sh` — универсальная daemon-обёртка для систем без привычной init-системы.
- Добавлены эталонные файлы:
  - `assets/defaults/config`;
  - `assets/defaults/ipset/zapret-hosts-user.txt`;
  - `assets/defaults/ipset/zapret-hosts-user-exclude.txt`.
- `core/service.py` стал init-agnostic: статус и управление сервисом выбираются по обнаруженной системе инициализации.
- `core/zapret_config.py` при восстановлении baseline также возвращает whitelist в `data/whitelist.txt` и `/opt/zapret/ipset/zapret-hosts-user.txt`.
- `.gitignore` упрощён; `assets/defaults/ipset/zapret-hosts-user.txt` больше не игнорируется.

### Важные границы текущего среза

- Каталог `tests/` отсутствует; автоматических unit-тестов в этом срезе нет.
- `diagnosis_v2` — ручная визуальная диагностика, не автоматический ремонт.
- Live-тест встроенного апдейтера запускать только в отдельной копии проекта, не в основной dev-директории.
- Перед публикацией в `main` нужно перенести docs в `Repo/`, заменить raw-ссылки `/dev/` на `/main/` и превратить этот блок в релизную секцию `[1.3.0]`.

## [1.2.0] — 2026-10-24
Дата релиза: 2026-10-24. Ветка: `main`. HEAD источника: `dev` `f00a1d7`. Публичный релиз `v1.2.0`.

Файл `VERSION` содержит `1.2.0`; релиз опубликован в `main`.

### Визуальная диагностика и инструменты

- Добавлен `core/geo.py` — Geo/VPN-детекция: проверка туннельных интерфейсов через `ip link` и получение IP/провайдера через HTTP-источники с fallback.
- Добавлен `core/dns_resolver.py` — локальный DNS-резолвинг через `socket.getaddrinfo`, без sudo и внешних утилит.
- Добавлен `core/html_checker.py` — HTTP/HTML-проверка доступности по конкретному IP через `curl --resolve`.
- Добавлен `core/tools.py` — реестр инструментов `Tool` / `ToolRegistry` для UI-группы «Инструменты».
- Добавлен `ui/browser_widget.py` — мини-браузер на QtWebEngine с ephemeral профилем, memory HTTP cache и сигналами загрузки.
- Добавлен `ui/diagnosis_block.py` — визуальный каркас блоков диагностики.
- Добавлен `ui/diagnosis_widget.py` — сценарий `diagnosis_v2` с ручной цепочкой Geo -> DNS -> HTML и браузером-свидетелем.
- Добавлен `ui/target_domains_widget.py` — инструмент «Целевые домены»: ECH -> AUX -> Сборка -> Запись, плюс диалог просмотра/удаления target hosts.
- Добавлены фоновые воркеры: `ui/geo_worker.py`, `ui/dns_worker.py`, `ui/html_worker.py`, `ui/ech_worker.py`, `ui/aux_worker.py`, `ui/assembly_worker.py`.
- `ui/site_passport.py` интегрирует выбор сценариев и инструментов, диспетчер запуска, безопасную остановку воркеров и создание паспорта после диагностики.

### Config / blockcheck / UI

- `core/zapret_config.py` — единый менеджер чтения и записи `/opt/zapret/config`: атомарная запись, lock-файл, кэшированный пароль sudo, валидация, кэш чтения, `set_many()` и иерархия исключений.
- Blockcheck сохраняет strategy bundle по схемам и протоколам; fast-режим не останавливается на первой найденной стратегии и дожидается SUMMARY.
- Для HTTP предпочтение отдано `nfqws` вместо `tpws`, чтобы не ломать другой трафик.
- UI применяет strategy bundle по protocol slots: HTTP, HTTPS, HTTP/3.
- Добавлено минимальное действие baseline restore.
- Поддержана multiline-валидация стратегии в `backup_config`.

### Installer / updater hygiene

- `install.sh` устанавливает QtWebEngine-пакеты для apt/pacman/dnf/zypper.
- `install.sh` добавляет/проверяет DNS-утилиты и `iproute`/`iproute2` для Geo/VPN-детекции.
- Проверка установки усилена тестом импорта `PyQt6.QtWebEngineWidgets.QWebEngineView`.
- Финальная проверка установки теперь контролирует доступность `curl`, `dig` и `ip` в PATH.
- `core/updater.py` продолжает использовать релизный канал `main`: `VERSION`, `docs/CHANGELOG.md` и ZIP архив ветки `main`.

### Важные границы текущего среза

- В релизном срезе `v1.2.0` отсутствует каталог `tests/`; unit-тесты не входят в этот срез.
- `diagnosis_v2` — ручная визуальная диагностика, не автоматический ремонт.
- Инструмент «Целевые домены» записывает target hosts только в уже существующий паспорт сайта.
- Старая экспериментальная линия с боевым apply/pipeline/live passport не входит в релиз `v1.2.0`.
- Live-тест встроенного апдейтера не следует запускать в основной dev-директории; для этого нужна отдельная копия проекта.

## [1.1.1] — 2026-10-07

- Проверка обновлений переведена на чтение `VERSION` из ветки `main` без обязательных GitHub Releases.

- Прогресс загрузки использует `Content-Length`, если размер не передан заранее.

## [1.1.0] — 2026-10-07

### Обновления
- Добавлена проверка новых версий через GitHub Releases API.
- Добавлен файл `VERSION` как источник текущей версии приложения.
- Добавлен диалог «О программе» с информацией о текущей/доступной версии и release notes.
- Добавлен индикатор доступного обновления в главном окне.
- Добавлено скачивание ZIP-архива обновления в `~/.cache/zapretpass/downloads`, staging в `~/.cache/zapretpass/staging`, бэкапы и fallback-архивы в `~/.local/share/zapretpass`.
- Добавлено применение обновления с промежуточным бэкапом и откатом при ошибке.
- Добавлено сохранение состояния обновлений в `data/update_state.json`.

### Ядро
- Portable-режим: `PROJECT_DIR` вычисляется динамически как `Path(__file__).parent.parent`.
- `blockcheck.sh` запускается в неинтерактивном режиме `BATCH=1`; настройки передаются переменными окружения.
- Исправлен fast-mode детект первой рабочей стратегии: парсер ориентирован на реальный вывод `working strategy found`.
- `stdin` процесса блокчека используется только для пароля `sudo -S` и затем закрывается.

### Установщик
- Добавлен `install.sh` для Ubuntu/Debian-based, Manjaro/Arch и Fedora.
- Установщик ставит системные и dev-зависимости, клонирует/обновляет `/opt/zapret`, собирает бинарники при необходимости, регистрирует systemd-юниты, создаёт `zapretpass.sh` и desktop-ярлык.

### UI
- Главное окно получило интеграцию с системой обновлений.
- Добавлены диалог «О программе» и индикатор обновления.

### Документация
- Синхронизированы публичные документы `STRUCTURE.md`, `PROJECT_MANIFEST.md` и `README.md` после изменений portable/BATCH/installer/updater.
- `WORKLOG.md` переведён во внутренний документ `Work/WORKLOG.md` и исключён из git/релиза.

### Известные ограничения релиза
- Апдейтер в текущей реализации заменяет верхнеуровневые папки целиком. Все внутренние файлы должны жить в `Work/`, чтобы не удаляться при обновлении. После применения ZIP восстанавливаются exec-биты для `install.sh`, `zapretpass.sh` и `zapretpass.py`.
- Текст обновления в диалоге парсится из `docs/CHANGELOG.md` ветки `main`; fallback — тело GitHub Release, если секция не найдена.
- ActivityGuard и финальная интеграция перезапуска/очистки backup/staging находятся в разработке.

## [0.1.0] — 2026-09-18

### Ядро приложения

Первый релиз с полноценным ядром, отделённым от пользовательского интерфейса.

**Добавлено:**
- core/config.py — пути, инициализация директорий, шаблоны конфигов
- core/service.py — управление systemd-сервисом zapret (старт/стоп/статус)
- core/sudo.py — запрос и кэширование пароля, выполнение привилегированных команд
- core/strategies.py — стратегии, пресеты, whitelist, поиск пересечений/объединений
- core/blockcheck.py — запуск и парсинг blockcheck.sh с интерактивными ответами
- core/applier.py — применение стратегий и режимов к конфигу
- core/sniffer.py — перехват SNI-доменов через tshark
- core/checker.py — проверка доступности сайтов через curl

**Архитектура:**
- Ядро полностью отделено от UI (не импортирует Qt)
- Мультисистемность через машинно-читаемые форматы (systemctl show, cgroup)
- Симлинк-подход для движка zapret (самодостаточная установка)

**Документация:**
- docs/STRUCTURE.md — карта проекта
- docs/PROJECT_MANIFEST.md — карта модулей, форматов данных, зависимостей
- docs/WORKLOG.md — журнал работы между сессиями

**Следующие шаги:**
- Qt6-интерфейс (ui/)
- Установщик движка (installer/)
- Unit-тесты (tests/)
