# Changelog

Все значимые изменения проекта документируются в этом файле.

## Unreleased / dev

Дата состояния: 2026-10-17. Ветка: `dev`. Кодовая база: `16184e8`. Публичный релиз в `main` не делался.

Файл `VERSION` содержит `1.2.0` как планируемый следующий релиз; до стабилизации и живого теста эта версия не публикуется в `main`.

### Текущее состояние после отката диагностической ветки

- Из активной линии `dev` исключена ветка с диагностическим core, apply-слоем, pipeline/live passport и тестовыми модулями.
- Публичная структура теперь описывает только реально существующие модули `core/`, `ui/`, `data/`, `resources/` и `docs/`.
- Каталог `tests/` в текущем срезе отсутствует; unit-тесты диагностического стека не входят в это состояние.
- Это по-прежнему dev/unreleased, а не релизный `main`.

### Ядро: Zapret Config Manager и managed config

- Добавлен `core/zapret_config.py` — единый менеджер чтения и записи `/opt/zapret/config`.
- Атомарная запись через временный файл + `mv`.
- Lock-файл для защиты от гонок данных.
- Валидация входных данных и иерархия исключений.
- Кэширование чтения с TTL.
- `set_many()` для массового обновления нескольких параметров за одну транзакцию.
- `set_strategy()` переключает `NFQWS_ENABLE` / `TPWS_ENABLE` и формирует scoped OPT с hostlist-маркерами.
- `read_strategy()` возвращает активную стратегию по ENABLE-флагам.
- Добавлено управление целевым хостлистом для scope обхода.
- Добавлена генерация чистого ZapretPass managed config из strategy bundle.

### Blockcheck

- Результаты blockcheck сохраняются как strategy bundle по схемам и протоколам.
- Fast-режим больше не останавливается на первой найденной стратегии и дожидается SUMMARY.
- Для HTTP предпочтение отдано `nfqws` вместо `tpws`, чтобы не ломать другой трафик.
- Убран дублирующий builder strategy bundle.
- В метаданных сохраняется контекст теста: tool, args, test, scheme, ipver.

### UI

- Интеграция `ZapretConfigManager` в workflow blockcheck.
- Scoped strategy apply block и отложенное сохранение паспорта.
- Применение strategy bundle по protocol slots: HTTP, HTTPS, HTTP/3.
- Добавлено минимальное действие baseline restore.

### Config / installer

- Перписан парсер конфига для поддержки многострочных значений.
- Поддержана multiline-валидация стратегии в `backup_config`.
- В `install.sh` добавлены DNS-утилиты для основных пакетных менеджеров.

### Важные границы текущего среза

Текущий срез `dev` не содержит диагностический core, apply-слой, pipeline/live passport и тестовые модули из отдельной экспериментальной линии. Эти файлы отсутствуют в HEAD и не должны упоминаться как доступные для импорта.

## [1.1.2] — 2026-10-07

### Обслуживание обновлений
- Добавлена ротация старых артефактов обновления: хранятся последние 3 бэкапа, 3 скачанных ZIP и 3 fallback-архива.

## [1.1.1] — 2026-10-07

### Исправления обновлений
- Проверка обновлений переведена на чтение `VERSION` из ветки `main` без обязательных GitHub Releases.
- Текст обновления парсится из `docs/CHANGELOG.md` ветки `main`, с fallback на GitHub Release body.
- Постоянные бэкапы и fallback-архивы перенесены в `~/.local/share/zapretpass`.
- После применения ZIP восстанавливаются исполняемые биты для `install.sh`, `zapretpass.sh`, `zapretpass.py` и других `.sh` в корне.
- Добавлен ActivityGuard: блокировка повторных проверок/обновлений и закрытия окна во время операций.
- Бэкап обновления исключает `Repo/`, копирование игнорирует `.git`.
- Прогресс загрузки использует `Content-Length`, если размер не передан заранее.

## [1.1.0] — 2026-10-07

### Обновления
- Добавлена проверка новых версий через GitHub Releases API.
- Добавлен файл `VERSION` как источник текущей версии приложения.
- Добавлен диалог «О программе» с информацией о текущей/доступной версии и release notes.
- Добавлен индикатор доступного обновления в главном окне.
- Добавлено скачивание ZIP-архива обновления в `~/.cache/zapretpass/downloads`, staging в `~/.cache/zapretpass/staging`, бэкапы и fallback-архивы в `~/.local/share/zapretpass`.
- Добавлено применение обновления с промежуточным бэкапом и откатом при ошибке.
- Добавлено сохранение состояния обновлений в `data/update_state.json`.

### Ядро
- Portable-режим: `PROJECT_DIR` вычисляется динамически как `Path(__file__).parent.parent`.
- `blockcheck.sh` запускается в неинтерактивном режиме `BATCH=1`; настройки передаются переменными окружения.
- Исправлен fast-mode детект первой рабочей стратегии: парсер ориентирован на реальный вывод `working strategy found`.
- `stdin` процесса блокчека используется только для пароля `sudo -S` и затем закрывается.

### Установщик
- Добавлен `install.sh` для Ubuntu/Debian-based, Manjaro/Arch и Fedora.
- Установщик ставит системные и dev-зависимости, клонирует/обновляет `/opt/zapret`, собирает бинарники при необходимости, регистрирует systemd-юниты, создаёт `zapretpass.sh` и desktop-ярлык.

### UI
- Главное окно получило интеграцию с системой обновлений.
- Добавлены диалог «О программе» и индикатор обновления.

### Документация
- Синхронизированы публичные документы `STRUCTURE.md`, `PROJECT_MANIFEST.md` и `README.md` после изменений portable/BATCH/installer/updater.
- `WORKLOG.md` переведён во внутренний документ `Work/WORKLOG.md` и исключён из git/релиза.

### Известные ограничения релиза
- Апдейтер в текущей реализации заменяет верхнеуровневые папки целиком. Все внутренние файлы должны жить в `Work/`, чтобы не удаляться при обновлении. После применения ZIP восстанавливаются exec-биты для `install.sh`, `zapretpass.sh` и `zapretpass.py`.
- Текст обновления в диалоге парсится из `docs/CHANGELOG.md` ветки `main`; fallback — тело GitHub Release, если секция не найдена.
- ActivityGuard и финальная интеграция перезапуска/очистки backup/staging находятся в разработке.

## [0.1.0] — 2026-09-18

### Ядро приложения

Первый релиз с полноценным ядром, отделённым от пользовательского интерфейса.

**Добавлено:**
- core/config.py — пути, инициализация директорий, шаблоны конфигов
- core/service.py — управление systemd-сервисом zapret (старт/стоп/статус)
- core/sudo.py — запрос и кэширование пароля, выполнение привилегированных команд
- core/strategies.py — стратегии, пресеты, whitelist, поиск пересечений/объединений
- core/blockcheck.py — запуск и парсинг blockcheck.sh с интерактивными ответами
- core/applier.py — применение стратегий и режимов к конфигу
- core/sniffer.py — перехват SNI-доменов через tshark
- core/checker.py — проверка доступности сайтов через curl

**Архитектура:**
- Ядро полностью отделено от UI (не импортирует Qt)
- Мультисистемность через машинно-читаемые форматы (systemctl show, cgroup)
- Симлинк-подход для движка zapret (самодостаточная установка)

**Документация:**
- docs/STRUCTURE.md — карта проекта
- docs/PROJECT_MANIFEST.md — карта модулей, форматов данных, зависимостей
- docs/WORKLOG.md — журнал работы между сессиями

**Следующие шаги:**
- Qt6-интерфейс (ui/)
- Установщик движка (installer/)
- Unit-тесты (tests/)
